The project in numbers

How it works

The app is React Native, with login, chat and past conversations. Each message goes to a Python server, where a sentiment module names the emotion in it and a DistilGPT-2 model, using the QuAC dataset, writes the reply. Firebase Realtime Database handles logins and user information.

The module names one of eight emotions: joy, sadness, anger, fear, surprise, disgust, trust or anticipation. Knowing the emotion lets the reply console or celebrate.

The deployment plan

The C-Day abstract describes the Azure deployment as a plan. The report sized it two ways. For a fast-growing user base, two Azure NC6s_v3 GPU servers, one on the east coast and one on the west, each with a replicated Firebase database, so a regional outage would not take the app down. For an early, small user base, one server and one database in the east.

One hard decision

Every message goes through the sentiment module before the reply. Without it, as the report puts it, the model was a basic conversationalist; with it, the reply can console a sad message or celebrate good news.

One limit

The report’s test fed the 10 labelled prompts to the backend and noted only the emotion it detected. It ignored the replies and reports no accuracy figure; the report’s reason is that testing an LLM widely is costly.

The evaluation lab shows how I evaluate a classifier instead, on open data: a held-out test set, bootstrap intervals, a threshold you can move, and failures picked by rule, not by hand.
