Problem
How do you give coding agents clear roles, and delivery context they can read but not change?

I built the workflow: specialist coding subagents, read-only MCP servers for Jenkins and Bitbucket, and a searchable knowledge base compiled automatically from work sessions.

How it fits together

One hard decision

Each handoff between agents costs something. The receiving agent gets a summary instead of the full context, and a task that dies midway has to be handed off again.

My conclusion: keep one agent in charge of integration and commits, and add specialists where an independent check is worth more than the handoff. The multi-agent workflow I built is set up that way: one subagent implements, one reviews, one verifies, and they get read-only access to delivery tools.

One limit

In the recorded run, 8 of its 52 steps ended in an error, and 6 of those are followed by a recorded retry or fix. Both tasks that stopped midway and left partial edits behind were delegated worker tasks. One was interrupted and one lost its connection, and both were resumed.

There is no second run with more or fewer agents, so the trace cannot tell you whether this split beat one agent doing everything.
